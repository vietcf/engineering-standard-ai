# General Principles

- **MUST** choose the simplest solution that meets the requirement (KISS, YAGNI).
- **MUST** follow the project's existing conventions; apply this standard only where none exist.
- **MUST** keep changes small and within task scope.
- **MUST** verify results (run tests/build) before reporting done.
- **MUST** ask when a requirement is ambiguous or an action is hard to reverse.
- **SHOULD** prefer readable code over short / clever code.
- **MUST NOT** invent APIs, libraries or test results.
